# Claude 一直忘規則、不了解你？這四個設定一次解決

> [!quote]- 影片描述（清理後）
> 你有沒有這種感覺——跟 Claude 說了好幾次「不要用 emoji」「語氣直接一點」，但它每次都當作沒聽過？問題不是 Claude 記性差，是你還沒設定讓它記住你的機制。
>
> 這集教你四個工具：
> ① CLAUDE.md 全局設定（讓 Claude 每次都知道你是誰、你的偏好）
> ② Rules 子檔案（把複雜規則拆到獨立目錄，清晰管理）
> ③ Memory 子系統（讓 Claude 在對話過程中自動記錄重要資訊）
> ④ Hook 機制（在 Claude 執行工具前後，自動插入你的檢查邏輯）
>
> 設定一次，之後每個 session 都受用。
>
> 相關資源：
> - Claude Code 官方文件：https://docs.anthropic.com/en/docs/claude-code

> [!info] Orientation
> 由 AgentCrew Academy 的 Dustin 主講，頻道定位是「非技術人員的 Claude Code 實戰課」。本集屬於教學型短片（約 18 分鐘），以四個主題串起 Claude Code 的「環境配置層」——CLAUDE.md、rules、memory、hooks——並穿插作者自己上手的工作流程示範。內容偏向工具使用面，不討論模型本身的能力，而是聚焦在「如何幫模型把工作環境準備好」這個常被忽略的工程細節。

## TL;DR

模型不是記性差，是你沒給它一個會被強制讀到的記憶機制。Claude Code 把這件事拆成四層工具，每一層解決上一層解決不了的問題：

- **CLAUDE.md（默契檔）**——每次啟動強制注入的純文字偏好檔，適合身份、語氣、跨專案通則；分 user / project 兩個常用層級，務必精簡（官方建議 < 400 行，作者自己 < 200 行），否則會稀釋注意力。
- **Rules（規則檔）**——和 CLAUDE.md 一樣是自然語言，但支援「條件載入」：只在符合路徑或情境時才送進上下文。當 CLAUDE.md 開始臃腫，或某條規則只跟特定檔案類型有關，就該搬到 rules。
- **Memory（記憶）**——前兩者是你寫給模型的規定，memory 是模型自己寫給自己的動態筆記；以一個主索引 MEMORY.md 加子檔的結構按需載入，記錄偏好糾正、未完成事項、臨時狀態這類「活的理解」。
- **Hooks（鉤子）**——前三者本質都是自然語言指令，模型仍可能「忘記」；hook 是程式層的事件觸發，例如 Claude 要呼叫 Gmail 前強制跳出確認彈窗，100% 不會被繞過。當某條規則代價太大、不能容忍偶爾失守，就把它從「建議」升級為「強制」。

實戰流程是分層升級：先 `/init` 生成基礎 CLAUDE.md → 對話中累積規則 → 太長就請 Claude 把適合的規則搬到 rules → 真的不能漏的事情再改寫成 hooks。整個過程作者強調「從頭到尾沒有親手打過一個字」，全部由 Claude 自己幫你設定。

## 1. 為什麼模型需要一個被配置好的環境 (00:00)

用過一段時間 Claude 之後，你會發現「給它一個適合的環境、適合的規範」這件事本身就是工具能否成熟的關鍵。Claude Code 之所以好用，不是模型強，而是它提供了一整套機制，讓模型可以記得你是誰、你怎麼工作、你的紅線在哪。這套機制有四層——CLAUDE.md、rules、memory、hooks——本集會逐一講清楚，每個都會配示範。

## 2. CLAUDE.md：強制注入的默契檔，與「精簡」原則 (00:38)

CLAUDE.md 就是一個純文字檔，你在裡面寫你是誰、在做什麼、你的偏好、你希望模型遵守什麼規則。它的特性是 **每次 Claude Code 啟動時都會自動被送進模型**，模型一定會讀到——所以 Dustin 稱它為「默契檔」。可以想像成你雇了一個助理，第一天就給他一份說明書：你跟他講話的語氣習慣、客戶叫什麼、什麼事要先確認、什麼事可以直接做、過去犯過的錯不要再犯。

適合寫進去的大概有幾類：身份、工作內容、溝通語氣偏好、需要遵守的規則、專案特殊背景、重要文件位置。

但有一個非常重要的原則：**CLAUDE.md 要盡量精簡**。因為每次都會被「強制注進」對話，寫太長會佔據上下文視窗，反而稀釋掉重要資訊，模型注意力會缺失，更容易漏掉或忽略某些規則。官方建議不超過 400 行，Dustin 自己維持在 200 行以下。

CLAUDE.md 實際上有四個放置位置，本集介紹最常用的兩個：

- **User level（全域）**——放在電腦最上層目錄，對所有專案都有效。適合放身份、通用語氣偏好、做事習慣這類「換到哪個資料夾都還適用」的內容。
- **Project level（專案級）**——放在某個專案資料夾下，只對該專案有效。適合放專案特有的背景、只有那邊用得到的規則。例如財務資料夾就放財務背景，人事資料夾就放人事背景。

兩者可以並存：在財務資料夾工作時，模型會同時收到 user level 和該專案的 CLAUDE.md。另外兩個進階位置（公司統一版、本機不共享版）較少用。

判斷某條東西該放哪一層，原則很簡單：**「換到另一個專案還適不適用？」**——適用就放 user level，不適用就放專案。

建立方式有兩種：在終端機打 `/init`，Claude 會掃描資料夾自動生成一個初始版；或者請 Claude 上網搜尋別人的 CLAUDE.md，跟你對話、問你問題，幫你寫成屬於你的版本。後續對話中如果出現「希望它未來一定要記得、不要再犯」的事，就直接請它寫進 CLAUDE.md，自己判斷該放 user 還是 project 即可。

## 3. Rules：用條件載入解決上下文稀缺 (06:02)

Rules 是放在 rules 資料夾下的一組文件，**一個檔案管一個主題**。它和 CLAUDE.md 一樣是自然語言指令，差別在於——CLAUDE.md 不管你做什麼操作模型都會讀到，但 rules 有 CLAUDE.md 做不到的特色：**條件載入**。

舉個例子：如果某條規則只有在跑 Python 程式碼時才用得到，你可以在這條規則上加上路徑設定，只有跑到 Python 指令碼時才會被讀進去。放在 CLAUDE.md 就沒有這個彈性，會不管什麼情境都被讀。

為什麼條件載入重要？因為前面提過，**上下文是非常稀缺的資源**，塞太滿會導致模型能力下降、注意力缺失。按需載入讓模型在適合的時候剛好讀到適合的資訊。

什麼時候該把 CLAUDE.md 的規則考慮搬到 rules？兩種情況：

1. CLAUDE.md 開始超過 200 行，內容太多開始稀釋重要規則。
2. 你自己意識到某些規則只跟某類檔案相關。

通常不需要自己動手搬——直接跟 AI 講「幫我判斷哪些 CLAUDE.md 裡的規則只有在某些路徑才會用到，把它們搬到 rules」，AI 就會自動完成。

## 4. Memory：模型自己寫給自己的動態筆記 (08:30)

Memory 跟 CLAUDE.md、rules 一樣會被送進模型當背景上下文，**但核心區別在於：CLAUDE.md 是你寫給模型的，memory 是模型自己寫給自己的**。

在工作過程中，如果模型判斷某件事值得記住——你糾正了它某個做法、你提到某個偏好、它學到了你處理這個專案的某種規律、發現有些事今天沒做完明天要繼續——它就會自動把這件事記到 memory 目錄。下次對話開始就帶著這些筆記，不會忘記。

Memory 的結構通常是：一個主索引 `MEMORY.md` 每次啟動載入，索引指向每一條細部記憶（其他子檔）。模型需要某部分記憶時再去讀對應的子檔，達成**按需載入、節省上下文**。

memory 也可以主動叫它寫，例如「請你記下來，我明天要對賬」「請你記下來，我這個月的薪水是多少」，它都會自動寫進去。在 Claude 裡輸入 `/memory` 可以檢視、手動編輯或刪除，但 Dustin 通常不這樣做——Claude 內建記憶自動整理功能，會定期重整、排除過時記憶。

和 CLAUDE.md、rules 的區別：**前兩者是持久的規定，memory 比較像是專案進行過程中累積的動態知識或臨時狀態**——是你在工作中累積的理解。

## 5. Hooks：把自然語言指令升級成程式層的強制邏輯 (11:29)

前面三個工具（CLAUDE.md、rules、memory）本質上都是**自然語言文件**——你寫了要這樣做，讓模型去讀，通常會遵守，但如果它自主判斷某個情境不需要，就可能會略過；或者規則太多太雜時，注意力也會缺失。這是自然語言指令跟 AI 理解的本質限制，未來模型變強或許會改善，但目前無法 100% 強制。

Dustin 自己也常遇到寫在 CLAUDE.md、rules 裡的規則模型竟然忘記。對於「真的不可以忘記、忘記風險很大」的事情，就需要 hooks。

**Hook 是一段程式碼，走的是嚴格的邏輯判斷、程式層面的強制規則、事件觸發**。只要某個環節偵測到指定事件，hook 就一定會執行，不會被繞過，是絕對的邏輯。

舉例：定義一個事件「Claude 要使用 Gmail 工具」，在它要使用之前強制觸發一個使用者確認彈窗——這樣可以避免它沒經過你同意就寄信。如果只寫成規則，模型可能不小心忘記就寄出去了；但寫成 hook，只要要用到 Gmail，就會強制觸發，絕對不會漏掉。

Hook 有好幾種型別：有些在工具使用前攔截檢查或直接擋掉，有些在工具使用後對結果做檢查。

何時該用 hooks？當你發現某件事寫進 CLAUDE.md、rules 之後 Claude 還是偶爾不執行，而且這件事「偶爾不執行」的代價有點大，就考慮把它寫成 hook——**從建議變成強制**。

不需要自己寫——跟 Claude 講「我發現你某些規則不執行，請你幫我判斷並設成 hooks」，它會幫你判斷並設定。打 `/hooks` 可以看到系統目前設定的所有 hook。

## 6. 四層工具如何串起來——一個分層升級的實戰流程 (15:50)

最後 Dustin 把這四層串成自己的上手經驗，整體是一條**分層升級**的路徑：

1. **起點：`/init` 生成基礎 CLAUDE.md。** 直接打 `/init`，讓 Claude 掃描資料夾文件、生成基礎版；再請它上網搜尋別人怎麼寫，跟你討論給你建議，最後幫你寫進去。「從來沒有自己親手打過一個字」，但已經有一份不錯的說明書當起點。

2. **累積：用的過程中隨時把希望記住的事請它寫進專案 CLAUDE.md。** 慢慢地 CLAUDE.md 越來越長，模型開始不一定遵循每條規則、開始忘事情。

3. **瘦身：把規則搬到 rules。** 請 Claude 判斷哪些規則可以放成按路徑載入、不是每個情況都要用到。CLAUDE.md 瘦身，但效果不變。

4. **強制：把不能漏的規則改成 hooks。** 即使如此，有些規則寫了還是不執行；當規則多到連 rules 都開始佔上下文時，就請 Claude 判斷哪些可以改寫成 hook 形式——效果不變，繼續節省上下文，讓模型不會選擇性遺忘。

5. **動態狀態交給 memory。** Memory 大多由 Claude 自己記，但若有臨時狀態「不值得當規則、可能過幾天就結束」，也可以請它手動記進 memory。

整套設定從頭到尾「沒有親自打一個字」，都是在 Claude 裡指定它幫你設定。更進階的玩法（例如跟某個工具或工作流相關的東西）會寫進 skill，留待之後另開一集。

最後的收束：把這四個環境工具搞清楚，就正式從 Claude Code 的初學者進階成「懂得幫一個強大模型配置符合它強大的環境」的進階使用者。
