# 翁家翌：OpenAI，GPT，强化学习，Infra，后训练，天授，tuixue，开源，CMU，清华｜WhynotTV Podcast #4

> 这是中文科技访谈播客 **WhynotTV Podcast** 的第 4 期，一场约两小时的长访谈。嘉宾翁家翌（Jiayi Weng）是 OpenAI 研究员，2022 年加入，搭建了 OpenAI 内部的 post-training RL infra，是 GPT-3.5 到 GPT-5 一系列模型背后的核心贡献者。在进工业界之前，他是清华本科、CMU 硕士，并以开源强化学习框架"天授（Tianshou）"和免费签证查询系统"退学 online（tuixue.online）"为人所知。这期内容兼具个人成长史与 OpenAI 的内部视角，适合关心 AI 行业、RL/infra 技术路线，以及"工程能力 vs 研究能力"这类职业选择问题的读者。

## TL;DR

翁家翌的经历串起一个反复出现的论点：在今天的 AI 里，**idea 很便宜，能把 infra 做对、快速且正确地迭代才是真正稀缺的能力**——这也是他从"误入强化学习"一路走到 OpenAI post-training infra 核心位置的主线。

- 他从小给自己的人生设了两个度量：**"投资未来"**（学得慢，所以提前学）和**"impact"**（人生的结算分数是记得你名字的人数）。开源作业、天授、退学 online 都是这套价值观的产物——做工具是一种"慈善"。
- 他很早就看清强化学习的学术研究是"玄学调参"，自己不喜欢也不擅长，于是选择**"卖铲子"**：搭好 infra 让别人去玩、去发论文。
- 在 OpenAI，他的核心判断是 infra 的正确性与迭代吞吐量决定模型好坏——"谁修的 bug 越多，谁的模型训得越好"；他预测 researcher 会比 infra 工程师更早被 AI 取代。
- 他给出 OpenAI 的内部视角：ChatGPT 的爆发是"半偶然半必然"、没人预料到；闭源是公司生存的 trade-off；组织变大后真正的生死线是 **infra 的 cycle time** 与"信息无损流通"的一致性。
- 访谈后段转向一个意外私人的话题：他相信世界是确定性的、人没有自由意志——一个他"想证伪却证不了"、也不愿接受的世界观。

## 1. 一个想"投资未来"的小孩：从奥数到 OI 竞赛

翁家翌从一年级起学奥数，不是被父母逼的——父母对他怎么学并不太关心——而是因为初等数学太无趣，稍难一点的数学才提得起他的兴趣。他对自己的判断有个反直觉之处：他认为自己学得**慢**，学一个新东西要花别人两三倍的时间（直到现在读一段代码也是如此）；但一旦理解，他用得极快，因为他会直接建立一条捷径（shortcut）连到知识树的顶端，不必每次从根节点逐层推一遍。

正因为学得慢，他的对策是**提前学**：与其把时间浪费在刷题上，不如学一点对未来有用的东西，后面的收益会更大。他把这件事明确地称为"投资未来"——初二啃完高中数学，初三开始学微积分。驱动他的不是天赋自觉，而是正反馈：一次初始的成就感、一个初始的 reward，然后数学这一支的技能树就一格一格点亮，每点一次都有正反馈，于是一直走下去。篮球和跆拳道没有正反馈（实战被人按着打），就没继续。编程从初一的兴趣班开始，纯粹"报着玩"。

到了高中，搞 OI 信息学竞赛的动机则现实得多：对非北京的学生来说，不靠竞赛想上清华北大"难如登天"。他放弃了数学竞赛（省选太难、起步太晚），全力转向 OI。结果是一个"黑历史"：他是当年福建省队倒数第一，全省唯一的铜牌。在此之前他已经做了一个艰难的赌注——选了"无条件降 60 分"录取清华，而不是 NOI 现场签上海交大的稳妥保底。对不确定性的恐惧让这个决定很难，但家人的鼓励让他押了清华。

## 2. 在清华"打破信息差"：把作业开源

问到清华本科最值得回忆的事，他第一个想到的是：把自己所有的作业开源。这件事在学长学姐里有争议，有人反对，但他认为自己应该做。他收集了能拿到的所有"上古作业、上古材料"，除去有版权问题的，其余全部传上 GitHub。

理由只有一个词：**打破信息差**。信息差在清华是个很有用的东西，但他认为每个人都应该平等地拥有这个信息。他的论证是从受益者的角度出发的：很多人其实很有能力，只是不擅长搜集东西，于是疲于奔命——一道作业卡住十几二十个小时，又不敢问助教，时间被钻牛角尖耗掉，对学习收益极低。把作业开源，就是给这些人一个"信息平权"的机会，让他们把时间花在更想做的事上，而不是浪费生命。这件事做成了：他的作业如今是清华广为流传的 GitHub repo——用他自己半开玩笑的话，比往系楼上捐钱还更被人记得。

## 3. 误入强化学习，和"卖铲子"的觉悟

他进入强化学习是个相当随机的选择。大二进朱军老师组时有三个方向——贝叶斯、GAN、强化学习。他本想搞 GAN，因为图像生成很有意思，但他当时是个"小白"，根本不知道哪个是 GAN，误以为 RL 是搞图像的，就选了 RL。第一个项目是用神经网络通关 VizDoom（一个 90 年代游戏），还拿了冠军。

但他并不享受这个过程。原因很本质：当时的 RL 任务环境太单一，你要疯狂 overfit，用各种 heuristic 技巧防止训练崩掉，即使没崩也不知道怎么调参才对——"这个是真的炼丹"，调参难度比 CV 难上十倍百倍，全是玄学。他由此得出一个很早、也很关键的认知：**改算法其实没那么本质，瓶颈在环境和实现**。对人类简单的任务，对 RL 却极难，因为它需要大量先验知识。

于是他有意识地把重心从"做研究"转向"让这类研究更顺利"。他发现自己非常擅长软件工程那一面——重构代码、把抽象做对、把用户体验做好——而对调参有"生理上的排斥"。这就是后来他反复用的比喻：他更喜欢**卖铲子**。把根基打好，做一个 playground，让别人去玩、去发论文，发论文时可能带上他。这个觉悟直接通向大四的天授，也通向他后来在 OpenAI 的整个职业路径。

## 4. Bengio 暑研：撞上算力与工程的墙

大三申请暑研，套磁信发了一堆没结果，最后是导师帮他联系上了 Yoshua Bengio，2019 年暑假去了 Mila。这段暑研"做得也没那么成功"。Bengio 和带他的博士后给的任务是做一个类似 MoE 的东西——但当时还没有 MoE 这个概念，只有一个"router 选择不同 path"的 idea，让他去实现。

任务本身就很拧巴：他是做 RL 的人，却被派去做纯语言模型（Transformer / NLP），花了很长时间才入门，搓出来的东西也没什么效果。但他事后的反思才是重点：这件事**当时根本做不出来**，而且"哪怕当时有了现在的认知，那还是做不出来"——因为缺的不是 idea，是 engineering 能力和 compute。一个人几块卡，做不出需要 scale up 的东西，方向对也没用。这是他第一次切身撞上那堵墙：在前沿问题上，资源和工程能力会先于想法成为瓶颈。

他对前 ChatGPT 时代 NLP 的判断也在这里成形：NLP 任务太分散；当时很多人想把 RL 用到语言模型训练上，但 Transformer 直接跑 RL 很容易崩，没人想清楚怎么防。后来才被证明：环境要"纯"（纯文本），reward 要足够强。

## 5. 申请受挫，挣脱固有的评价体系

暑研没出成果，回清华准备申请时整个人状态不好——周围同学去 Stanford、CMU 暑研都发了一作 paper，"不然你会被别人刷下去"。他对着 PhD 申请，最后只拿到 Master。在清华内部那种"PhD 一定优于 Master"的鄙视链里，这确实是一种挫败，他花了一段时间才调整过来。

但这次受挫推着他想明白了一件他本科只挣脱了一半的事：**评价体系**。他一直觉得 GPA 不是唯一的评价体系——你在 GPA 拿第一，总有人比你强；从需求方（比如招聘方）的角度看，相关经验远比 GPA 重要，匹配的经验甚至能抵好几年工作经历，哪怕你是应届生。本科时他对 GPA 的策略很极端：用最低限度的时间达到够用的标准，"多一分都不想花"，87 分的 B+ 就很满足。

他真正的转变，是从"否定官方评价体系"走到"建立自己的评价体系"。他采用了导师苏航给的一套非官方标准——计算机系值得追求的三个指标：论文、比赛、GitHub 三位数以上的 star。这给了他一个完全不同的想法：他可以在开源社区做出与众不同的东西。值得注意的是他对这套标准的态度——他只对自己这么要求，不强加于人；而且他不做这个标准的奴隶，标准不合适就改。

## 6. 天授与退学：把做工具当成一种慈善

19 年底他有个强烈的冲动：自己已经写了很多 RL 实验代码，为什么不整合起来让实验跑得更好。20 年 2 月他先看了 Ray 下的 RLlib，想改一改来支持自己的实验，看了一个月——几十万行代码、抽象太多，完全不能接受，连"我要改的东西该怎么实现"都不知道。于是干脆推倒重来，手撸天授。

第一版只花了两周。他给出的解释很有说服力：如果你把抽象搞对，实现一个算法可能不到 20 行。RLlib 之所以膨胀，是因为合作的人多了、每个人贡献一点，项目逐渐"腐化"。他由此提出一个贯穿全片的工程观点——一个项目最有用的东西是 **consistency（一致性）**。腐化几乎都源于不一致：十个人各写一点，互相不知道对方的 assumption，假设无法及时传递，于是到处复制粘贴、代码不断膨胀。天授成功是因为它抓住了真实的用户需求（researcher 想要一个好用好改的 RL 框架），代码短、抽象做得还行——"你想改什么地方，设计已经帮你设计好了，只能改这"。

退学 online（tuixue.online）是同一套逻辑的产物：疫情期间领事馆时开时关，他自己有实时查签证名额的需求，找了一圈没有满足需求的东西，就手撸了一个签证爬虫并免费开放，累计点击量上千万。两个项目都不功利——天授发生在申请之后、他也明说不想发 paper（"发 paper 完全没有意义"，他已经有 paper、申请也够用了）。他把做这种 non-profit 的工具称为做**慈善**：哪怕亏钱也行，重要的是产生影响力。

## 7. 追求 impact 的底层逻辑

这一段把前面所有"开源""慈善""投资未来"背后的价值观摊开。他追求 impact 的起点是高三某天突然冒出的一个想法："如果人生是一场游戏，那么游戏的结算分数，是记得你名字的人数。"——他想让自己死的那一刻，记得他名字的人越多越好。

他自己一开始也不觉得这重要，是试了几次发现这确实是他想要的：做出能给他人带来好处的东西，他自己认可、他人也认可，然后从他人那里得到正反馈。但他把 impact 和"名气（fame）"明确区分开——名气可能是负面的、对别人收益不一定为正；他要的是别人发自内心的认可，是一种共识。

主持人在这里抛出一个尖锐的张力：他想挣脱外部评价体系（GPA、PhD>Master），可他给自己的内在标准——别人的认同——本质上又是外界的评价。翁家翌承认了，但做了一个关键区分：他想摆脱的是"现有体系和成规"的评价，他想要的是每个人发自内心的点赞——可以是 GitHub star、退学的点击量、Google Scholar 引用，也可以是 OpenAI 模型每天的 inference 次数。他也清楚这只是他对自己的要求，不会拿它去评价下一辈年轻人；而且他不为这个标准所困——有很长一段时间他没有开源项目，也不觉得困扰，因为"OpenAI 的 model 就是最好的影响力"。

## 8. CMU、求职，与加入 OpenAI

疫情中他申请到 CMU，原本该 2020 年 9 月入学，结果第一学期在家上网课，上了一年。一入学他就得想找工作。一开始"吊儿郎当"投了 18 家，只收到 Google 和陈天奇的 OctoML——他不想去 Google 当"大厂螺丝钉"做前后端。想明白一点后再去面，拿到了幻方的 offer（幻方当时要做的 AI Lab 就是后来的 DeepSeek，岗位是 RL infra），还有英伟达、TikTok 等。所以事后开天眼地看，他当时面临的其实是 **DeepSeek 还是 OpenAI** 的选择。

他选了 OpenAI，而且必须强调这是"在 ChatGPT 之前"——当时没人知道 ChatGPT is coming。理由是 OpenAI 和 DeepMind 是当时 RL 做得最好的两个研究实验室，能进就已经非常好；他想体验世界最前沿的研究到底是怎么做的、有什么方法论，而不是像学校里"几个 PhD 手搓一个东西、没有方法论"。

招他的是 John Schulman，他对此非常感激——Schulman 离职那天他难过了一下午。Schulman 欣赏他，正是因为认可他那套评价体系：他的 GitHub 很漂亮，而招一个有良好工程能力的人对任何项目都有益。最后一轮面试 Schulman 出了一道很 end-to-end、很开放的题，给三小时，他两小时就从头写完做完，现场出了个 bug 也当场修好。这道题只测过两个人——他，和现在做 Codex 的 Andrey——两人都通过了。

## 9. 为什么不读 PhD：idea 便宜，infra 才是关键

他从没考虑过读 PhD，理由很直接：如果你想进工业界，读 PhD 就是"浪费生命"。你完全可以用 master 做跳板，在本科或硕士阶段攒够 citation、做出与众不同的项目，去和同期的 PhD candidate 同台竞技——关键是想清楚**差异化**。他很早就确定自己的未来一定在工业界：学术界教书当教授太卷，还要为项目拉 funding，限制太多。

谈到工程能力 vs 研究能力，他引用了一位同事（曾是 RL PhD、做过知名 RL 框架）的话：**"教一个 researcher 如何做好 engineering，要远比教一个 engineer 如何做好 research 来得难。"** 他的论证是：前沿研究实验室拼的其实是 infra 的正确性——infra 对了，就看你单位时间能迭代多少次。而 idea 非常便宜：大不了找人讨论一下就出来了；真正动脑子的是像 Alec 那种从 GPT-1 就在领域里、有很强研究直觉的人，找他讨论就好。你要做的，是在单位时间内验证尽可能多的有效 idea，而且要建立在正确的 infra、正确的结果、快速的迭代上。

由此他把自己的整个职业策略讲透了：他不愿做调参那种 research，他要"卖铲子"——而且要做卖铲子里最面向客户的那一位，因为 RL 处在整个 infra 生态位的最顶端，是每个人都想要的东西。他甚至给自己定了个 reward：最大化自己的名字出现在 OpenAI blog 上的次数。要最大化这个，就得做 infra：单个 research 不能 scale up，而 infra 大家都用、可以 scale up。"OpenAI 很多 model release 都有我的名字，就是因为我在内部搭了整个 post-training 的 RL infra。"

## 10. 进入 OpenAI：RLHF、post-training 与 ChatGPT 的意外引爆

他先给出两个干净的定义。**强化学习**：如果你能把一个环境建模、在环境中得到反馈，那这个循环就是 RL，靠反馈越学越好。**post-training**：他 2022 年 7 月刚进 OpenAI 时根本还没有 pre-train/post-train 之分，团队就叫 RL。

他入职时 GPT-3.5 内部已经有了，但当时的 PPO pipeline 非常不好用，用得最广的其实是 3.5 的 SFT。一个反直觉的事实：RLHF 是**先在 GPT-4 上调通的**——新 infra 22 年中刚好，他先在新 infra 上跑通第一版 PPO、用 GPT-4 跑（约 22 年 9 月），之后 3.5 上才成立。当时 Schulman 的 RL team 在做 WebGPT 的后续：3.5 直接做 browsing 效果很差（browsing 需要 tool call），于是退而求其次先把 chat 体验做好——chat 可以用 RLHF 的 instruction following 来解决。

关于 ChatGPT 的成功，他的内部视角很清醒：**没人预料到**。他能内测模型，但只觉得"是个会说话的模型，能帮一点代码问题，也就这样"，因为他有循序渐进的过程、不觉得突然；突然的是发布后身边的人的反应。发 ChatGPT 本身只是想收集一些真实用户数据，团队预期可能一两万用户然后跌回去就关掉，实际曲线却是指数级。22 年 7 月全公司并没有 all in ChatGPT，只有他们一个组在做。他把整件事总结为"一系列半偶然半必然的因素的化学反应"。他对 OpenAI 的初印象也不像想象中那么有方法论——更像"一个大号的实验室"，但里面有很多研究直觉很强的人能指明方向；真正带来方法论的，是 Barret、Luke、Liam 三个人从 Google 来之后引进的"先进生产力"。

## 11. 工业级 RL infra：修 bug 的吞吐量决定一切

从 Google 引进的"先进生产力"其实是一种哲学：先不要想天才的 idea 和算法，把 infra 打好——让迭代从一周 30 次提到一周 300 次。有一张图说明了一切：单位时间的迭代次数和成功率成正比，迭代越多，成功率线性往上走。这本身就是一条 RL 曲线，因为 RL 就是不断 trial and error。

22 年要把 RLHF 搞 work，最关键的挑战不是算法，而是**怎么衡量性能**——谁都不知道性能"应该"是什么样。单一 reward 会发生 reward hacking：reward 可能 saturate 成一条直线一直涨，但真实情况可能是先升后降，于是你无法知道哪个 checkpoint 真的更好。他们的解法很朴素：建一堆 sampling-based eval 看各 benchmark，但 benchmark 只是个数、方差很大噪音很多；最后还是得把模型拉下来真的交互几次、多找几个人投票——也就是说，evaluate RLHF 还是得用 HF（人类反馈），当时技术上没有别的办法。

他点出工业级 RL infra 和天授那种 toy-task infra 的本质区别：toy task 的瓶颈在环境（模型小，训练采样都便宜）；工业级则相反——环境极简单（就是一个 prompt），但模型极大，提供 prompt 只要几微秒，跑一遍 inference + training 却要几百到几千秒，于是高效采样、高效训练成了真正的难题。这个位置极其锻炼人也极其累——他有一段时间一周工作六七天、从早 debug 到晚，累到进了急诊室（医生说没事）。也因此他养成了每周跑两次 3000 米的习惯。

他给出整片最锋利的一句判断：**"每一家的 infra 都有不同程度的 bug，谁修的 bug 越多，谁的模型训得就越好。"** 他甚至猜测 Llama 训不过 GPT 可能就是因为 bug 太多。现在他已经不在最核心的位置，而是带组**推倒重来**重构 OpenAI 下一代 infra——上一代用了三年多，technical debt 太多。researcher 不参与写 infra，他们只提需求、到时候改一个 flag。

## 12. 瓶颈、AGI，与"researcher 会先被取代"

谈未来 5–10 年的瓶颈，他的答案始终如一：**修 infra 的吞吐量**——单位时间内能正确地修多少 bug、正确地迭代多少次，剩下的都不重要，因为这能赋能其余一切。"如果你把 bug 全修了，算法可能连改都不用改。"他认为现有路线还没 scale up 完全，应该先让它慢慢 hill climb、把现有方法和现有算力榨干，再看下一步——所谓"没 scale up 完"指的是性能还没榨干，不是算力不够。

关于 agent：他认为 agent + RL post-training 和标准 LLM + RL post-training **没有本质差别**，本来就是同一个东西，只是中间多了几步 tool call、环境多一点。

关于 AGI：OpenAI 内部的笑话是"抓 15 个人有 20 种定义"。他自己的定义是能完成他认为有意义的任务的 80%–90%。他认为现在还没到——因为他还不放心 AI 直接上手改他的 infra 代码：AI infra 在训练数据里占比几乎为 0，是高度 out-of-distribution 的，而且验证反馈链太长、成本太高。他还讲了一个清醒的观察：strawberry 出来前内部用过一阵，当时大家都觉得"工作要被取代了，干脆先写屎山，等模型训完帮我们清理"——一两年过去，屎山还在那。每个人都会 overreact，但技术其实是一个很慢、循序渐进的过程。

他给出一个有点黑色幽默的预测：被 AI 取代的顺序是 **researcher 先于 infra engineer**——因为 researcher 的工作就是想 idea、验证 idea，而 idea 可以很便宜地被生成；infra 需要更多 context 所以更难。而 sales 反而最难取代，因为说服人买单还是要人与人之间的沟通。

## 13. OpenAI 还 Open 吗

面对"OpenAI 已经和 open 没关系"的批评，他承认这是一个 **trade-off**，并且认同它。他自己仍然热爱开源，但他把公司的使命拆成两半看——"实现 AGI"和"造福全人类"。实现 AGI 就是堆 RL/pre-train/算力、scale up；而当下"造福全人类"的拆解方式是做产品、用尽可能便宜的价格（比如免费的 ChatGPT、免费的语音模式）让普通人能接触到技术。所以 OpenAI 的 open，不是对其他大模型公司 open，而是对**普通人** open——直接丢一个裸的模型权重，普通人也不知道怎么用。

主持人追问：如果到 AGI 还有很长的路，更开放、拿社区反馈，会不会反而更快？他承认理论上存在"开源 + 接受社区反馈 + 更快实现 AGI"的路径，但执行上有很多困难，核心是博弈论：你是第一，一旦开源，别人马上变第一，再训一下然后闭源——不是所有人都同条心，有人就是想挣钱。在这种环境下 OpenAI 可能融不到资、没有人持续输血，所以不得不闭源。他也坦白，如果 OpenAI 有无限资源、永远不用担心生死，他会非常开心地把这两三年的 RL infra 开源出去——Schulman 确实问过他要不要开源，他当时出于公司考量觉得不太好。他还确认：DeepSeek 至少 open weights 这件事，让 OpenAI 内部重新做了一轮评估。

## 14. 内部视角：Sam 被开除、人才流失与 AI 竞赛

对 23 年 11 月 Sam Altman 被开除，他给的内部视角戳破了外部的玄幻传言（"Ilya 到底看到了什么"都是捕风捉影）：真实情况就是 Ilya 和一些董事会成员不信任 Sam 这个人，投票把他投出去；而底下干活的人非常震惊，因为董事会对下面缺乏透明度。结局是 Ilya 走、Sam 回——因为很多员工觉得，纯技术出身的人领导没那么多远见：实现 AGI 不只靠技术，还要融资、要算力、要说服人投钱，长远看需要 Sam 这样的人。Sam 因此可能是 AI 最难被替代的那个人——他是一个 personality、一个 identity，短期内换成 AI，别人对这个 ID 的认同感就会缺失。

对 OpenAI 成功后大量人才流失，他认为这不可避免，而且一个健康的组织本就该是所有人都可替代的——只要持续培养新人、有"造血能力"，像干细胞一样。这也意味着 OpenAI 做的东西外面的人并非不能复刻："把最简单的东西做好就好，没有什么黑魔法。"

外部竞争（xAI、Anthropic、中国大模型公司）一般不会传导到内部日常开发，唯一的例外是 DeepSeek 那一波——他们在 Twitter 上声称迭代速度极快，引起了警觉，因为 OpenAI 内部的迭代速度其实偏慢，这正是要重构 infra 的原因。他点明对一家基座模型公司来说，真正的**生死线是 infra 的 cycle time**：data、算法、researcher 数量都只是投人就能解决的人力，而 infra 需要更多 context。他也承认 OpenAI 在"单位时间迭代速度"这个指标上不是世界第一——抽出一个小团队去做 startup，斜率一定远高于 OpenAI，因为代码库小、沟通成本少、只需聚焦少数 use case。组织变大必然变慢，这是人类组织发展到一定规模无法避免的问题，根源是 **context sharing 的一致性**难以维持，infra 和组织结构都开始臃肿。他由此引出一个设想：理论上应该有一个拥有无限长 context 的 agent 来当 CEO，负责所有的信息共享和决策——可能没有比这更合适的决策者了。

## 15. 决定论、创业念头与十年后的自己

访谈尾段转向一个意外私人的话题。翁家翌相信这个世界是**确定论**的：我们生活在一个确定性的马尔可夫过程里，人没有自由意志——他此刻在想什么、下一个词说什么，"宇宙大爆炸那一刻就定好了"。这是他"已经验证了无数遍"、想证伪却证不了的结论，而他内心深处并不愿意接受——那会让他觉得自己只是一个被模拟的原子。他给出的两个自洽解释：宏观不掷骰子、微观掷骰子（量子观测层面可以"在后台修改世界线"）；以及时间在四维里并非单向，"未来的我"可以帮"过去的我"完成某些决策——他追求 impact 的那个念头，就是高三时凭空蹦出来的一句话，他至今不确定是不是未来的自己发来的。如果真有能预测未来的 AI，他认为那对个人是灾难、会让整个价值体系崩塌，人类最好的选择是毁掉它。而他面对这一切的方式是：忘掉它，假装不知道，去体验当下——"还坚信西西弗斯是幸福的"。

关于创业，他承认心里可能有种子，但还没看到很好的 idea，而且 OpenAI 对他仍是个不错的地方。他更喜欢偏 product 的方向——像天授、退学那样有真实用户、能根据反馈实时迭代的东西；他强调"技术什么样不重要，重要的是抓住需求"，退学第一版甚至是他手动一天更新两次签证时间。

最后问到十年后的自己，他的回答收束回贯穿全片的两个词。他希望那时的自己能做自己想做的事、有足够的资源和能力——而他现在能做的就是"投资未来"的翁家翌，给他选择的权利。一个诚实的转折出现在结尾：他曾经一度想通了自己想要什么，但现在又想不通了——曾经热爱的 RL infra、做有 impact 的事，"因为已经看到头了，剩下都是很确定性的事情"。他正处在人生的某个迷茫期。他留给听众的最后一句话，也是留给自己的：去探索，说到底自己到底想要什么——这个问题值得用一生去思考。
